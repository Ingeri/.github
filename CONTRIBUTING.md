# Contributing

Thanks for helping improve Ingeri's open-source work and GitHub community files. Before opening an issue or pull request, check the project's README and existing discussions so feedback reaches the right repository.

## Issues

Use the bug report template for reproducible defects and the feature request template for a proposed improvement. Include the relevant repository, expected behavior, actual behavior, and enough detail to reproduce or evaluate the request. Do not include passwords, access tokens, private user data, or other secrets.

## Pull requests

1. Fork the relevant repository and create a focused branch.
2. Keep each change small and explain the user-facing reason in the pull request description.
3. Run the checks documented by that repository. For documentation-only changes, preview the Markdown and check links and spelling.
4. Link related issues and note any follow-up work or limitations.

Be respectful in reviews and discussions, follow the [Code of Conduct](CODE_OF_CONDUCT.md), and do not include unrelated formatting or generated files. Maintainers may ask for changes or close contributions that are outside a project's scope.
